# C2C 预测市场产品框架

> 版本：v0.21（2026-08-04）
> MVP 工程需求见 `mvp-engineering-requirements.md`（注意：v1.1 尚未同步 v0.19"砍 CLOB、加 C2C"、v0.20"creator 主权结算、砍 UMA/存证"、v0.21"入金三梯队"变更）
> 定位：**去中心化 UGC 预测市场协议**——C 端用户（主播为主力创建者）发起话题，观众/朋友下注，链上去中心化结算。架构为"无许可协议 + 旗舰前端"双层。
> 与 Polymarket 的核心差异：话题是**海量长尾的、主观性强的、自带社交分发的**——这个差异决定了下面所有架构选择，不能照抄 Polymarket。

---

## 1. 市场机制：彩池一级市场 + C2C 二级市场（核心架构决策）

**基本原理**：被动报价方（AMM LP 或策略简单的 MM 机器人）在预测市场必然被知情流薅——结果代币最终收敛到 0 或 1，被动报价等于一路给知情者送钱（Polymarket 早期 AMM 靠流动性挖矿补贴 LP 才撑住，2022 年底转向 CLOB）。

**决策一：不做 AMM。** 曾考虑"受限 AMM"作为中间层（只上客观话题、赛前冻结、LMSR 封顶亏损），但约束只能让 LP 亏损可预算，不能消除；深度完全依赖主播或平台持续掏钱补贴，主播不掏就没深度，平台掏就变成与用户对赌的庄家——一个"有时有深度、有时没有"的机制层比没有更糟。

**决策二：不做 CLOB（v0.19 修订，推翻 v0.18 的"品类适配制"分层）。** 原方案为客观品类配 CLOB + MM 机器人生态。砍掉的理由：CLOB 的真实成本不是订单簿本身，是喂养它的整个做市生态——MM 软件、maker 返佣、报价挖矿、DMM 签约、品类上线门槛，全部是为"让订单簿有深度"支付的制度成本；即使平台永不持仓，这套生态也只在高频客观品类转得动，长尾主观盘永远没人报价。替代方案是 **C2C 转让市场**（本节下文）：流动性来源从"专业报价方"换成"想退出的持仓用户"，挂单是主动定价决策，逆向选择由挂单人自己消化——"被动报价被知情流薅"的结构性问题在单边市场不存在。**有意放弃的东西写明**：体育用户"下注即锁赔率"的预期彩池给不了，这是取舍而非疏漏——赛马业百年就是纯彩池模式；cash-out 与盘中交易需求由 C2C 转让承接。

| 层 | 机制 | 流动性来源 | 窗口 | 取消处理 |
|---|---|---|---|---|
| 一级市场（全品类统一） | **彩池 parimutuel**（单池多桶） | 不需要——用户互为对手 | 开盘 → 封盘 | 每份 1 USDC 退当前持有人，无纠纷 |
| 二级市场（全品类统一） | **C2C 卖单转让**（类 OpenSea 固定价挂单） | 持仓用户自己的仓位 | 下注后 → 结算终局 | 挂单中份额随时无条件撤回 |

**彩池的两个必答设计题**（没有 AMM 后需正面解决）：

- **晚下注激励**：彩池赔率到封盘才确定，越晚下注信息越充分，理性玩家会挤在最后一刻，前期池子冷清。对策：**早鸟返还**（从抽水中拿一部分返还早期下注者，池子分配公式不动）+ 事件开始前提前封盘。曾考虑时间加权派彩，但加权后"池子比例 = 实际赔率"不再成立，展示与派彩脱钩，用户会觉得被骗——弃用
- **赔率展示**：池子比例实时换算成隐含概率/赔率展示，体感接近固定赔率，但明示"最终赔率以封盘为准"

### C2C 转让市场设计（v0.19 新增）

**仓位资产化**：彩池份额发行为 ERC-1155（tokenId = 盘 × 桶），1 份 = 1 USDC 本金，同桶份额完全同质——挂单可任意拆分、部分成交，买家比价只看单价。**早鸟返还与份额分离**：按"原下注地址 × 下注时间"单独记账，转让不带走——奖励的是早期把钱投进池子的行为，卖掉份额不影响领取。

**市场形态：只挂卖单。** 固定价挂单（N 份 @ 单价），份额托管进合约；买家直接吃单，可部分成交；撤单随时，改价 = 撤 + 重挂。无买方出价、无撮合引擎、无价格优先级队列——同质化份额 + 双边挂单 ≈ 订单簿，这条线不越。买方出价（类 OpenSea offer）列为后续迭代项，触发条件 = 挂单成交率持续低迷、"急售无门"反馈集中出现。

**两段行情（核心产品逻辑；v0.20 随结算即时化从三段简化回两段）**：

- **封盘前**（下注后即可挂单）：池子永远按 1 USDC/份无限量供应新份额，C2C 挂单天然只能折价成交（前端把 >1 的挂单折叠并提示"池子直买更便宜"）——这一段 C2C 是**退出通道**：急用钱、改主意的人折价割给捡便宜的人
- **封盘后 → 结算前**：池子关闭，C2C 成为唯一入口，自由定价（可高于 1）——这就是**免做市商的盘中交易 + cash-out**：直播进行中、比赛开赛后仓位价值剧烈波动，恰好是转让需求最强的时段。Polymarket 需要 CLOB + 做市生态才能提供的东西，"彩池发行 + C2C 流通"复现大半，且平台零持仓、零流动性补贴
- **终局即停**（不是一段行情，是一个瞬间）：creator 一键结算 / API 触发 / 超时作废即终局——停止新挂单、未成交挂单可撤回，胜方份额直接 claim 派彩。结算是瞬时动作，不存在"提案—质疑"的中间态行情（v0.20）

**行情信号**：池子隐含概率与 C2C 最新成交价是两个独立信号——C2C 成交不改变池子比例、不影响派彩。封盘前并列展示，封盘后只剩 C2C 价；OBS 叠加层盘中展示 C2C 价，直播间从此有实时行情。

**作废语义（v0.19 更新）**：作废退款 = 每份 1 USDC 退给**当前持有人**，总退款恒等于总本金，无资金缺口；C2C 买卖差价自担（0.95 买入者作废赚 0.05，0.95 卖出者少拿 0.05）。作废预期升温时 C2C 价格自然抬向 1.0——这是合理的风险定价，不是漏洞。

**费用**：C2C 成交费设两个协议可配字段——平台费 + creator 分成（类 NFT royalty），**MVP 默认均为 0**。理由：结算抽水已在派彩时收过，二级市场重复收费会压制本就脆弱的退出流动性；字段是留给成熟期的运营杠杆，与创建话题费同一处理哲学。

**上限边界**：单用户/单池上限只约束池子入金（防赔率操纵），C2C 转让不受限——封盘后集中持仓不影响派彩公式。

**零系统签名**：挂/吃/撤全部是用户自己签名的链上交易，合约自治、挂单簿状态全在链上，任何前端可读取挂单、发起成交——旗舰前端只是 UI，挂了市场照转。对比两个都不引入的信任假设：签名订单模式（Seaport 式）依赖平台订单服务器的可用性；Polymarket CLOB 的 operator 签名在交易主路径上。唯一平台角色是 paymaster 代 gas（动不了资产）：C2C 操作纳入代付白名单 + 专项防刷限额（单用户每日挂单/撤单次数、最小挂单份额）；超限或代付故障走 USDC 扣 gas 兜底，用户全程不需要持有 gas 代币。

## 2. 话题系统

- **结构化模板**："X 是否在 Y 时间前发生，以 Z 为结算依据"。强制字段：结算源、截止时间、**取消/无效条款**（体育类默认"取消 → 作废退款"）。强约束模板是解决歧义的第一道防线——creator 主权结算下，命题越清楚，结算扯皮和差评就越少。
- **分类**：直播话题 / 体育 / 私密盘（朋友打赌，邀请制）
- **创建经济（v0.18 修订）**：**创建话题费**（协议参数，运营可配置为免费——冷启动建议默认免，成熟品类再开；推翻 v0.1"不收门票费"，保留为运营杠杆）+ 可退押金（防垃圾 + 担保**按时**结算——v0.20 起唯一罚没情形是超时弃盘，机械触发、无人裁量，与创建费相互独立）。**结算抽水归 creator**：creator 在合约硬上限内自设抽水率（防杀猪盘），平台从抽水中抽成——方向反转：不再是"平台抽水分给主播"，而是"主播抽水、平台抽成"，creator 是自己盘的第一收入人，开盘从成本项变成收入项
- **策展策略（已定：不审核，标注 + 投流分级）**：前端不设上线前审批门，三层处理——**红线类**（人身伤害、未成年人、隐私开盒）前端不渲染；**灰色/低质**展示但不投流 + 风险标注；**优质**投流推荐。LLM 自动打标：可判定性分（低分挂"结算标准模糊，creator 裁量空间大"警示）、依据登记（自愿登记结算依据链接，缺失挂"未登记结算依据"标）、可操纵性（"创建者可影响结果"标）、类目 + 创建者信用分。标注驱动投流与用户知情，配合作废退款与信誉评分构成"知情参与 + 用脚投票"闭环（v0.20：质疑/仲裁机制已移除，信任层是唯一纠错层）

### 标注体系（话题标注 + creator 信用分——前端两种权力的载体）

**话题标注（每个盘，LLM 开盘即打、秒级、事件触发重打）**：

| 维度 | 判定内容 | 触发的标签/处置 |
|---|---|---|
| 可判定性 | 主体/行为/时间界/结算依据是否齐备 | 低分挂"结算标准模糊，creator 裁量空间大" |
| 依据登记（v0.20 自愿制） | 是否登记结算依据链接（URL/回放） | 缺失挂"未登记结算依据" |
| 可操纵性 | creator 是否利益方、能否控制结果 | 挂"创建者可影响结果" |
| 类目 | 直播/体育/娱乐/私密 | 决定展示频道与结算模式 |
| 红线 | 红线类识别（人身伤害/未成年人/隐私开盒） | **唯一硬处置：前端不渲染**；误伤走申诉队列 |

重打时机：结算依据变更、封盘时间修改等关键事件。用途：投流资格与排序、下注页风险提示、展示限额。

**creator 信用分**：

- **输入（v0.20 重定义）**：结算记录（结算准时率、作废率）、弃盘罚没史、检测引擎信号（关联账户下注自己盘并获胜、刷量嫌疑）、结算后社区差评信号、累计盘量与结算额（资历）
- **分级**：新手 / 常规 / 优质 / 受限四档。新手默认低曝光，干净结算快速升档（前 N 个盘是爬坡期）；受限档（弃盘罚没/作废率异常/差评集中）盘默认不投流 + 显著警示
- **驱动**：投流权重、展示限额、默认曝光位——**信用是 creator 的流量资产**，诚实结算直接变现为曝光
- **原则**：链上行为永不受影响（无许可）；信用只分配前端资源；公式透明、可申诉

**标注的公开性**：标注与信用分对用户可见（下注前知情）、对 creator 可见（知道如何改进）、**开放 API 对其他前端可用**——去中心化生态下别的前端可以采用我们的标注也可以自己标，我们的标注是产品不是权力，它的影响力来自被信任而不是被强制。

### 开盘与标注流水线（无审批门，全量即时上线）

协议层开盘无许可，**所有盘即时可见**；前端不做上线前审批，LLM 标注异步完成（秒级），标注决定投流与风险提示——快不再是流水线的设计目标，是架构的默认属性。

1. **模板优先**：模板盘天然拿高可判定性分 → 获得投流资格。产品目标：90% 以上的盘走模板，自由文本盘默认低分不投流（LLM 附改写建议引导转模板）
2. **LLM 标注**：可判定性、证据可得性、可操纵性、类目、创建者信用分——全自动，秒级
3. **红线类拦截**：规则引擎 + LLM 识别 → 前端不渲染（唯一的硬性不展示）；误伤申诉走人工队列
4. **创建者信用**：干净结算记录提升投流权重与展示限额；弃盘罚没押金并降权——信用是主播的流量资产，反向激励诚实结算
5. **事后处置**：已展示的盘发现问题 → 前端下架/降权；链上照常走 creator 结算或超时作废。彩池红利依旧：**作废退款按份额机械执行，错放代价低**

配套机制：

- **预报备**：主播开播前提交当晚的盘，标注提前完成，直播中一键激活（零等待）
- **人工兜底**：只处理红线下架与误伤申诉，不参与常规上线流程

## 3. 结算体系：creator 主权结算（v0.20 重写——秒级派彩、全程零人工、协议不裁决）

**第一性原理（v0.20 换轴）：结算体系优化的不是"裁决正确性"，是"赢家多快拿到钱去玩下一个盘"。** 原设计（乐观结算 + 质疑窗口 + UMA 终审 + 存证层）为少数争议盘让全部盘承担了延迟与基建成本——小盘也要等 30–60 分钟质疑窗口，"结算 → 复投"这个生死指标天然带伤。v0.20 反转：**协议对结果内容零裁量**，结算权是市场参数、开盘时锁定、下注前可见；正确性问题移出结算层，交给信任层（知情标注 + 信誉评分）解决。

**话题编译原则保留**：话题创建仍是一次编译——把模糊问题编译成"明确主体 + 可观察行为 + 时间界"。模板与可判定性标注不再服务仲裁，服务两件事：**用户下注前看懂赌的是什么；creator 结算时少扯皮**。编译不过的话题（"结论是解读不是事实"类）挂"结算标准模糊，creator 裁量空间大"警示、不投流。

### 3.1 结算模式（市场参数，开盘锁定、下注前可见）

| 模式 | 适用 | 规则 |
|---|---|---|
| **creator 结算（默认）** | 直播/UGC/互联网事件盘 | 封盘后 creator 在时限内一键宣布结果（含作废）→ **链上即时生效、即时派彩**。无提案期、无质疑窗口、无仲裁 |
| **API 结算（Phase 2）** | 有标准数据源的客观盘（体育/币价） | 数据源与优先级开盘写死，keeper 触发，creator 无权干预；源消失/矛盾/腰斩延期 → 按预写条款作废退款 |
| **参与者共识** | 私密盘（朋友打赌，邀请制） | 全体/多数确认；僵局 → 超时作废退款，前端不裁决 |

**通用兜底（三模式共享，机械触发、无人裁量）**：结算时限超时 → 自动作废、全额退款（每份 1 USDC 退当前持有人）——资金在任何路径下都不会卡死，这是非托管承诺的结算侧兑现。

### 3.2 信任模型：协议 open，旗舰前端掌两权（v0.20 新增）

**creator 的权力边界 = 只能选结果。** 派彩公式、资金路径合约写死（见第 4 节资金与权限控制），creator 摸不到池子里的钱；最坏作恶 = 把结果判给自己（或小号）压的那边——对它的防线不在裁决层，在信任层：

- **协议层（open，无许可）**：任何人可开盘、下注、结算自己的盘，协议对结果内容零裁量。机制性保护只有三个（全部机械触发、无人裁量）：结算时限 + 超时自动作废；单池/单用户上限（开盘参数）；押金罚没仅一种情形——超时弃盘，罚没金随作废退款按本金比例分给该盘参与者，平台不经手
- **旗舰前端（我们的两项权利）**：**推荐权**——投流、排序、展示限额（低信用 creator 的大额盘不投流 + 显著警示）；**信誉评分权**——creator 信用档案公开可查（结算准时率、作废率、关联下注检测信号、社区差评、资历）。下注页强制知情标注：**"本盘由 creator 单方结算，协议与平台不裁决对错"** + creator 信用档案一键可见。标注与信誉开放 API，其他前端可采用也可自建——影响力来自被信任，不来自被强制
- **诚实结算的经济学**：creator 是公开身份的重复博弈玩家，抽水收入与曝光全部押在信用分上，诚实结算直接变现。**已知残余风险：单次杀猪**（攒信誉、杀大盘——单次背叛收益超过未来信誉折现时会发生）。信誉挡不住一次性背叛，上限 + 分级曝光是仅有的缓解，且协议无许可、约束不了其他前端——作为产品定位的一部分诚实接受，列入风险清单头部

### 3.3 证据自愿制（v0.20：替代原存证层）

creator 结算时可自愿附证据链接（直播平台回放/剪辑、截图、URL），前端随结算记录展示——**证据服务于信誉，不服务于裁决**。平台不建存证基建：v0.19 及以前的直播录制服务、网页快照服务、存证注册表、UMA 集成、质疑押金、保险基金全部移除。Augur 教训在 v0.20 语境下的重述：歧义盘照样致命，但解药从"证据 + 仲裁"换成"编译器（模板）+ 知情标注 + 信誉"——用户在下注前就知道这个盘由谁说了算、标准清不清楚，而不是在争议时找证据。

## 4. 交易与链上层

- 彩池合约（**单池多桶**：多结果事件用一个池 n 个桶，派彩 = 总池 ÷ 胜桶。不要拆成多个二元池——隐含赔率会互相矛盾、仓位割裂摊薄池子；二元拆分是订单簿的结构，不是彩池的。含早鸟返还；资金蜜罐，至少 1–2 轮审计）。原为 CLOB 层设计的"CTF 二元结果代币 + negRisk 联动"随 CLOB 移除（v0.19）——多结果事件由单池多桶原生支持
- **份额 token 化（v0.19 新增）**：彩池份额 = ERC-1155（tokenId = 盘 × 桶），下注铸造、claim 销毁；派彩与作废退款按**当前持有人**，早鸟返还按**原下注人**——两条独立 claim 路径
- **C2C 挂单合约（v0.19 新增）**：托管式固定价卖单，挂/吃/撤三个动作，成交 = 买家 USDC 过户 + 份额过户原子完成；M0 评估自建轻量合约 vs fork 有审计基础的成熟 marketplace 合约（如 Seaport 裁剪）——与彩池合约同批审计
- 微池子单位经济：结算批量化设计，避免链上成本吃掉小盘抽水
- 选一条低费 L2，USDC 计价（v0.20 注：UMA 砍除后，l2-selection.md 的头号选型理由"UMA 实战成熟度"失效，Polygon PoS 结论待复议——剩余理由为栈复用、低费、快终局与 AA 生态）

### 资金与权限控制（v0.19 新增；多签实现细节见工程文档 1.5）

**资金拓扑——用户本金只有一个沉淀点**：

| 合约 | 摸到什么钱 | 停留多久 |
|---|---|---|
| 彩池合约 | 全部本金（USDC）——唯一资金蜜罐，审计重心 | 下注 → 派彩/退款 claim |
| C2C 挂单合约 | **不沉淀 USDC**：只托管挂单份额，成交时资金与份额原子换手 | 份额托管至成交/撤单 |
| 押金托管 | 创建者可退押金；唯一罚没情形 = 超时弃盘，罚没金随作废退款按本金比例分给该盘参与者（v0.20，保险基金随仲裁层移除） | 结算终局释放 |
| 协议金库 | 只收费用（创建费、平台抽成、C2C 平台费），不含用户本金 | — |

C2C 合约不碰 USDC 存量是刻意设计：最坏情况被攻破，损失上限 = 当时托管中的挂单份额，池子本金动不了。

**权限五条硬规则**：

1. **资金路径不可升级、无管理员提款**：派彩、退款、C2C 结算、押金释放全走合约写死的公式，不存在任何 owner/多签可转走用户资产的函数；多签恶意凑齐门槛的最坏结果 = 参数调到合约硬上限 + timelock 公示期后生效
2. **多签只碰参数、参数有合约内置上下界**：费率、窗口分级曲线、押金下限、C2C 费用字段——全部带硬边界 + timelock；成员变更走更高门槛
3. **应急暂停只停新增、永不锁存量**：暂停范围 = 新开盘、新投注、新挂单（C2C 纳入），自动过期；**撤单取回托管份额、claim 派彩、作废退款永远不可暂停**——非托管承诺的合约级兑现
4. **偿付性由构造保证，不靠治理兜底**：派彩总额 ≡ 总池、退款总额 ≡ 总本金、份额铸销守恒、C2C 原子换手无中间态——写成合约不变量，进不变量测试 + fuzz + 审计范围
5. **keeper 无特权**：所有"自动"动作（封盘生效、超时作废、API 结算触发）无许可可触发、任何人可代为执行——不存在可被劫持的特权机器人角色

**C2C 专属两条**：挂单撤回无条件可用（不受暂停或任何市场状态影响——卖家的份额永远是卖家的）；成交费用分账 pull 而非 push（平台费/creator 分成先记账、各自领取，成交主路径不依赖外部转账成功）。

## 5. 用户端与主播工具

- **观众侧**：嵌入式钱包（无私钥心智）、gasless 代付、法币/USDC 入金、仓位与挂单管理（C2C 转让入口）、通知、排行榜。**入金摩擦是漏斗最大断点**（看到盘想下 $5，却要装钱包 + 入金几分钟），对策：首充赠金、预充值余额、入金通道做到 Apple Pay 级体验
- **主播侧**：一键开盘、**一键结算（v0.20：秒级派彩，主播在直播中当场结算发钱是内容高潮点）**、**OBS 直播叠加层实时显示赔率**（封盘后切换显示 C2C 行情价——直播间的实时行情）、分享卡片、分成后台——这是获客核心产品，不是附属功能

## 6. 用户路径（注册 → 入金 → 玩 → 出金）

**总原则：非托管贯穿全程**——钱包是用户的（密钥可导出），资金在链上属于用户；哪怕前端消失，用户导出密钥仍可拿回全部资产。前端提供的是通道和体验，不是保管箱。

### 6.1 注册/登录（目标：30 秒内可下注）

1. 观众扫叠加层二维码 / 点分享短链 → 落地页**未登录即可浏览**（命题、赔率、结算规则、标注全可见）
2. 点"下注"才触发登录：邮箱/手机号/社交账号 → 嵌入式钱包后台自动创建（无助记词、passkey 保护，小狐狸全程不出现）
3. 登录即注册——无独立注册流程、无表单

### 6.2 入金（v0.21 修订：Web2 路径从"第三方 on-ramp 弹窗"升级为三梯队）

**分层原则：协议只认 USDC，法币入金天然是前端层的事**——协议层对入金方式零感知。

- **Crypto 用户（MVP 主路径）**：向自己的钱包地址转 USDC，地址 + 二维码一键复制；跨链走内嵌桥（CCTP）
- **Web2 用户——法币入金三梯队**（第三方 on-ramp 弹窗被降级为兜底：类目限制、首次 KYC 摩擦击穿"30 秒可下注"、3–6% 费率对小额下注不友好、支付方式与目标市场错配）：
  1. **前端自营通道（目标态）**：用户用目标市场主流本地支付付款 → 前端从自营 USDC 资金池**即时打币到用户的非托管钱包** → 前端自行清算法币。体验 = 游戏充值：本地支付、秒到账、费率自控（可补贴到 0 作获客）、无第三方 KYC 弹窗；链上仍非托管。代价：自建收单、资金池运营与拒付/欺诈风控——资质与收单条件属前端层运营决策
  2. **本地持牌交易所引导深链（MVP 可上）**：引导式流程"在本地交易所用本地支付买 USDC → 一键复制地址提币到自己钱包"——成功率与费率远好于国际卡通道，工程量近乎为零
  3. **第三方 on-ramp 聚合（兜底）**：多供应商路由（Onramper/Meld 类）+ 亚洲通道，覆盖长尾地区与国际卡用户，不作主路径
- **投入节奏由入金漏斗数据驱动**：梯队二近零成本先上；漏斗证明"到站无钱"是最大流失点后，再投梯队一的自建
- 首充赠金在首次到账时触发；配合预充值心智（"充一次玩多晚"）摊薄单次入金成本
- gas 全程 paymaster 代付，用户永远不需要知道 gas 代币是什么

### 6.3 玩（核心循环）

下注（选桶 + 金额，一次签名；入口二选一：池子 1.0/份直买，或 C2C 折价吃单）→ 实时看池子赔率 / C2C 行情 → 随时可挂单转让（封盘前折价退出，封盘后自由价 cash-out）→ 封盘 → **creator 一键结算（v0.20：秒级派彩，无等待窗口）** → 赢家**一键 claim（gasless）** → 到账即可复投。"结算到再下注"之间零摩擦零延迟是复投率的关键——这正是 v0.20 砍掉质疑窗口的核心理由；"想退能退"降低下注时的决策门槛。

### 6.4 出金

- **Crypto 路径（始终可用）**：提 USDC 到任意外部地址（交易所/自持钱包），链上即时、无锁定期、无审批——非托管的直接推论：**我们没有能力也没有权利扣住用户的钱**
- **法币路径（off-ramp）**：内嵌 off-ramp（与 on-ramp 同批供应商）卖 USDC 回银行卡/账户；注意 off-ramp 地区覆盖普遍弱于 on-ramp，按首发市场逐一验证
- **兜底出口**：密钥导出——用户随时把钱包导入任意标准钱包（含 MetaMask），彻底脱离我们的前端

### 6.5 全链路埋点

注册转化、首充转化、首注转化、复投率、出金时长。两大生死指标：**入金漏斗**（6.2）和**"结算 → 复投"间隔**（6.3）。

## 7. 风险处理（去中心化重述：检测 + 标注 + 机制，而非管控）

协议无许可——我们无法也不试图阻止任何地址开盘或下注。原"风控"拆为三类：

**一、检测 + 标注 + 信誉（大部分）**：主播买自己的盘不禁止（skin in the game 是内容看点），挂"创建者可影响结果"标 + 持仓公示；小号/关联账户/女巫/对敲刷量——**检测引擎照建，输出从封禁改为信号**：进创建者信用分、决定投流权重与标注。不掌生杀权，只掌信息权和流量权。**封盘后内幕转让（v0.19 新增）**：C2C 让"封盘后无人能再交易"的天然防内幕屏障消失——creator/知情者知道结果后可在二级市场出货或接盘。处理同哲学：可操纵标签盘的 C2C 页挂显著警示、creator 地址的挂单与成交公示、异常转让模式进检测引擎与信用分；无许可原则不禁止交易

**二、机制设计（已在结算章）**：结算时限 + 超时自动作废、单池/单用户上限、弃盘罚没（机械触发）——写进合约、对所有人平等生效的规则，不需要执法者

**三、真正保留"控制"的仅一处**（"自有资金风控"已随"平台永不持仓"决策消失）：安全应急刹车——受限暂停（2/6、7 天自动过期），仅针对合约漏洞类安全事件，不用于市场干预；暂停只停新增（新开盘/新投注/新挂单），撤单、claim、退款永不可暂停——边界见第 4 节"资金与权限控制"

## 8. 商业模式

- **不发币（已定）**。连锁影响：无空投类增长手段，**主播激励 = 自己盘的抽水收入（USDC，平台仅抽成）**，收入看板升级为核心增长功能；治理永久多签，去中心化声明诚实收窄为"开盘无许可、资金非托管、结算权归 creator（协议不裁决）"三件事（v0.20：原"裁决外包"随 UMA 移除），不含治理；收入以 USDC 直接归金库，无代币价值捕获设计
- **收入（v0.19 修订）**：① 创建话题费（运营可配置，可免）② **主播抽水的平台抽成**（彩池层：抽水归 creator，平台按比例抽成）③ C2C 成交平台费（与 creator 分成并列的可配字段，MVP 默认 0——成熟期运营杠杆，冷启动期不压制退出流动性）。原"CLOB taker 手续费"与"参考赔率数据接口"随 CLOB/MM 生态移除。押金罚没不算收入，随作废退款分给该盘参与者（v0.20）——见结算章
- **支出（v0.20 修订）**：旗舰前端运营成本（策展/客服）、（Phase 2 起）**体育数据**（只剩赛前/赛后结算 + 展示用中档聚合商，约 $4–6k/月量级；原 Phase 3 的 Sportradar/Genius 级 Tier-1 重合同基本不再需要——盘中行情由 C2C 用户自行定价，没有 MM 需要喂低延迟官方数据）。原做市激励预算随 CLOB 移除、原预言机争议押金垫付随 UMA 移除
- **关键红线（v0.20 重述）**：结算零人工、争议零受理——客服不裁决结果争议（只处理产品与资金类问题），诚实结算靠信誉经济而非人工仲裁；运营成本随盘数近似为零增长，这是长尾模式成立的成本前提

## 10. 风险清单（按致命度排序）

1. **直播平台 ToS 风险**（增长引擎架在别人的平台上：主播挂实时赔率 = 博彩推广，平台一封获客归零。缓解：平台白名单匹配、官方合作、受限平台上以积分模式存在）
2. **creator 单方结算的信任风险 / 单次杀猪（v0.20 新增，替代原"主观话题的去中心化结算"）**（协议对结果零裁量后，攒信誉杀大盘没有硬防线——单次背叛收益 > 未来信誉折现时会发生。仅有的缓解：单池/单用户上限、分级曝光、强制知情标注、关联下注检测公示；协议无许可、约束不了其他前端。信任模型被大规模滥用是本产品最大的声誉赌注，MVP 验证目标之一）
3. **入金摩擦 × 双边冷启动**（看到盘想下注 → 装钱包/入金几分钟，热度已过；有盘无注。缓解路径见 6.2 入金三梯队）
4. **C2C 退出流动性稀薄**（"想卖没人接"= cash-out 卖点落空。缓解：封盘后转让需求天然最强、折价机制透明、买方出价与批量挂单工具视数据后补；C2C 成交率列入 MVP 验证目标）
5. **封盘后内幕转让**（C2C 使"封盘后无人能交易"的防内幕屏障消失——处理见第 7 节：标注警示 + creator 挂单/成交公示 + 检测信号进信用分）
