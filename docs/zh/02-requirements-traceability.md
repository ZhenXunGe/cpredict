## 1. 证据边界与状态定义

- `implemented_static` 仅表示当前仓库源码及聚焦本地证据支持，不代表 Arbitrum、生产或外审通过。
- `implemented_deviation` 表示已有实现，但与产品字面语义不同，必须由甲方/发布委员会书面接受。
- `partial` 表示只有部分实现或部分证据，不能标记完成。
- `external_required` 是该产品阶段必需，但由旗舰前端、基础设施、运营、法务或供应商承接；不是可选项。
- `not_implemented` 是当前没有合格实现。
- `deferred` 仅用于明确的 Phase 2、Phase 3 或条件触发的新市场类型。
- `decision_required` 表示没有冻结产品/发布决策前不能验收。

Arbitrum 或生产运行时已验证。

## 4. 验收和维护规则

1. 新需求只能新增稳定 ID；不得复用或重解释已有 ID。删除项保留 ID 并标为 superseded，同时指向替代项。
2. `source_lines.start/end` 必须处于锁定源文件 1-229 行，且 start 不得大于 end。
3. 状态只能使用 JSON 顶层 `status_definitions` 中的枚举；`implemented_static` 不得升级成部署或生产证明。
4. 每次源码、测试、部署或产品状态变化，先更新 JSON 的单项实现/证据/状态，再同步本可读视图。
5. 来源文件变更必须先更新 `requirements.lock` 的版本、bytes 和 SHA-256，再逐项审核 source line；
   不允许仅移动行号而不复核语义。
6. Release Candidate 仍受交付状态、安全门禁、外部审计、Arbitrum Sepolia E2E 和正式决策签字约束；
   本矩阵本身不是发布证明。
