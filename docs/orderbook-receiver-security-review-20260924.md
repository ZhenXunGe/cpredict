# Orderbook receiver recovery: Slither finding review

This review covers the replacement contract deployed to Arbitrum Sepolia on 2026-09-24 from `35fb874ec65a9c1ca439af37a6b0fc920da82593`. It does not change the older immutable marketplace or its existing rights. The full scan was rerun after V2 code entered the source tree; its previous checked-in report only listed two V1 findings. The exact High/Medium inventory is pinned by `validate-gate-evidence.mjs`; a new or removed item still fails validation. The deployment addresses, receipts and runtime acceptance are recorded in `docs/orderbook-autoclaim-release.md`.

| Finding | Assessment and evidence |
| --- | --- |
| `uninitialized-state` on `OrderbookMarketplaceV2.books` | False positive. Solidity mappings start empty; `_insert` is the only insertion path and initializes each dynamic heap on first write. Empty-book, price/FIFO, cancellation and heap tests pass. No constructor initialization is possible for an unbounded mapping key space. |
| `reentrancy-no-eth` on `fillOrder` and `matchOrders` | Receiver and fee-vault callbacks are external, but all order-mutating public entry points use `nonReentrant`. The one unguarded external transfer helper rejects every caller except `address(this)`; inherited ERC-1155 receiver callbacks only return selectors. The rejecting receiver and active reentry regression tests assert no partial trade or nested match. Recheck these findings if any new mutable entry point or callback is added. |
| `locked-ether` on `TradingSessionPolicyV1` and `TradingSessionPolicyV2` | Real but bounded policy-module limitation: Kernel-compatible hooks are payable and neither policy has an ETH withdrawal path. The protocol never funds these policies; they have no market/payment escrow authority. Sending ETH directly to a hook can strand that ETH. Do not send ETH to the policy address; a future policy version should reject nonzero value if provider compatibility is verified. V1 already exists on chain and is not changed here. |
| `unused-return` in V1/V2 `_bond`, `_listing`, `_order` | Intentional tuple destructuring. These checks use owner, market, side and active status; irrelevant getter fields are explicitly omitted and cannot alter permission decisions. Existing policy tests cover authorized and forbidden calls. |
| V1 `reentrancy-balance` in `_pullWithPermit2` | Previously reviewed baseline, unchanged by this replacement. Both paths use exact received-amount checks and guarded externally callable purchase/fill flows. |

The replacement's receiver transfer uses an isolated, gas-bounded self-call. A failed buyer delivery cancels and refunds only that bid; a failed ask return removes the order from the queue and records `pendingShares`, which only the original owner can withdraw to a chosen receiver. `OrderReleased` reports zero returned shares while deferred. Chain-indexed financial facts account for the return only when the later `OrderSharesWithdrawn` event and matching ERC-1155 transfer occur. A new factory, marketplace and permission policy were deployed; the old immutable contracts remain on chain, while the new test site uses a fresh database and does not expose their markets.
