# ctUSD 创建市场：规则发布失败调查与修复

## 真实故障证据

2026-09-11，上海时间（UTC+8），部署机实际容器和请求日志：

| 时间 | 来源 | 事实 |
| --- | --- | --- |
| 20:37:58 | metadata，`req-hb` | `POST /v1/challenges` 返回 200 |
| 20:38:17–20 | metadata，`req-he` | `POST /v1/markets` 返回 500，`PostgresError` |
| 20:38:20.020 | PostgreSQL | `market_publications` 写入违反 `market_publication_signature` CHECK 约束 |
| 20:38:20 | 网关 | `POST /ctusd/metadata/v1/markets` 返回 500 |

只读查询确认运行数据库的约束仍是 `signature ~ '^0x[0-9a-fA-F]{130}$'`，只接受 65 字节签名。HTTP 服务早已验证并接受最多 8192 字节的 ERC-1271/ERC-6492 智能账户签名；两者不一致，导致签名通过验证后落库失败。原事务回滚，该次挑战 `consumed_at` 仍为空。

运行 metadata Factory 为 `0xA62eEd107a5aa0924ee0Ba5a915f4B9B832C3913`，与 time-v2 site-config 一致；chain ID 为 421614。TTL 为 300 秒，这次挑战的到期时间是 20:42:58，失败时未过期。请求已走到提交签名后的 `/v1/markets`，不能归因为未取到挑战；日志本身不能证明 MetaMask 窗口的显示状态。

`CPREDICT_METADATA_PUBLIC_BASE_URL` 为公网 `/metadata`，站点调用 `/ctusd/metadata`。两个前缀均实测转到 metadata，返回 JSON；无效规则请求为 400，缺失规则为 404，没有 HTML、网关 401 或 502。旧 Factory 诊断请求得到 400 `{"error":"invalid challenge request"}`，无效发布请求得到 400 `{"error":"invalid request"}`。

历史访问日志没有保存响应体；该次 500 的响应体不能冒充为网络抓包。部署版本 `b563f04` 的已核对异常处理代码返回 `{"error":"internal error"}`，前端因此误映射为 `service_unavailable`。数据库错误日志提供了本次根因的直接证据。

脱敏请求记录和原始私有日志保存在部署机本次调查目录，私有日志不提交。没有复制连接串、用户签名或密钥到本文。

## 修复范围

- 新增 `002_smart_account_signatures.sql`，将存储约束调整为与现有服务一致的 1–8192 字节、偶数十六进制格式；保留 65 字节历史签名。只有存储格式改变，链、Factory、签名验证和一次性挑战校验保持有效。
- 在已有更新策略中登记该兼容迁移的 SHA256；不修改已执行的 001 迁移。标准更新仅需备份 metadata 数据库并短暂停止其写入者，再执行增量迁移；禁止使用旧备份覆盖新数据。
- 前端兼容 metadata 的字符串错误及 app 的对象错误，保留 HTTP 状态、响应类型、脱敏且有长度限制的响应诊断。页面显示具体原因，没有 operationId 时不要求用户提供操作编号。
- 服务明确区分 Factory 错误、挑战过期/已消费/不存在，以及已识别的签名存储约束错误；日志仅增加安全的 SQLSTATE 和已知约束名。
- 慢签名返回后若挑战已过期，停止发送过期签名。表单保留，用户再次点击会取新挑战并重新签名；不自动重签、不放宽 TTL。
- 本次不更改私有配置、合约、账户派生 index 1001、供应商密钥、额度或历史 schema。

## 部署与用户验收

首次部署的静态资源准备返回错误码 23；重查 316 个候选资源的大小与 SHA256 全部通过。第二次执行完成 metadata 备份与增量迁移，但并行重建时，动态分配地址的 App 容器占用了网关固定地址 `172.19.0.4`，Docker 记录 `Address already in use`，网关处于 created 状态。已释放冲突的动态地址、启动网关并用原别名重新动态连接 App，6 个容器恢复 healthy；没有修改私有配置或恢复旧数据库。

为完成本次部署并避免复发，更新与回退改为逐个启动后台服务、最后启动网关。后台更新期间网关持续占有固定地址。30 项更新工具测试通过，其中包含重现并行释放地址后被后台抢占的回归场景。公网资源校验仍在继续，未把中途失败写成部署成功。

部署验证结果将在执行现有 `stack:update:public` 流程后补充。真实 MetaMask 创建仍需用户手测：刷新后重新发布规则并签名，确认进入“核对创建交易”。如原来的封盘时间已过去，先改成有效的未来上海时间。此次自动化没有代替用户广播创建市场。
