# 市场初始化事件漏采与补采

## 本次问题

2026-09-16 对当前部署的只读核查确认：市场
`0x13f625675e01ee8c638bA3DF78D0f3e603C4d7Df` 在区块 `309356149` 创建。
交易 `0x936b0a2b66d4d6e247f87c6038260d9ef2d4d7d466be5b141b4b7aa5e95d135d`
的成功回执包含该市场的三条日志，包括 `MarketInitialized`、`MarketMetadataUpdated`。
现有解析器能正确解析；数据库保存了 Factory 的创建事件，却没有保存任何该市场的日志。
索引已超过创建块，因此继续追块不会补回这次缺失。

没有保存当时的 RPC 返回值，不能断言具体哪个节点或哪一次查询返回不完整。
代码原先存在两个缺口：首次 Factory 发现查询与随后范围查询不一致时，后者新发现的市场不会补扫；
范围查询缺失新市场日志时，没有初始化完整性检查，仍会提交检查点。

修复会补扫后发现的市场，并在初始化或规则事件缺失时核对创建交易回执。
两类事件必须来自同一市场、同一创建交易和区块；回执不可用、不完整或区块哈希不一致时，整个批次不落库。
回执正常完整时不增加额外回执请求。解析器和既有权益计算规则未修改。

## 上云后补采已有缺失市场

本次仅提交代码，未更新线上部署，也未修改线上数据库。
防漏采逻辑保护后续批次，不会自行修复已经越过检查点的历史缺口。
如果上云时保留现有数据库，应在新代码构建完成、索引运行配置指向正确部署后执行一次补采。

工具使用与 indexer 相同的私有运行环境，不要把凭据写入命令或日志。
在包含新构建产物的 indexer 运行环境内，先执行只读检查：

```sh
node dist/offchain/indexer/src/repair-creation.js 0x13f625675e01ee8c638bA3DF78D0f3e603C4d7Df
```

确认输出 `status: dry-run`、创建块 `309356149`、缺失日志数 `3` 后，显式执行：

```sh
node dist/offchain/indexer/src/repair-creation.js 0x13f625675e01ee8c638bA3DF78D0f3e603C4d7Df --apply /durable-backups/market-13f6-before.json
```

备份目录必须预先存在且可写，容器环境应使用持久化挂载。工具拒绝覆盖已有备份文件。
写入前会保存市场、检查点、已有交易日志和链上回执，文件权限为 `0600`。
数据库事务内再次检查目标市场并锁定事件/市场表，只允许修复没有后续市场事件、名称哈希与选项数均缺失的 Factory 占位记录。
补采同时更新原始事件、市场字段及该交易的财务事实，不回退实时检查点，不重置预算或交易状态。
已经修复、发生后续交易、来源交易不符或区块哈希不符时会拒绝执行。

执行后检查市场 API 中的 `rulesHash`、`outcomeCount`、`closeAt` 和规则标题，以及页面的名称、选项显示。
规则缓存刷新失败可能晚于数据库提交；如命令失败，应先查看快照与数据库现状，避免盲目重复操作。
旧部署使用 `stack:update:public` 时，历史投影输入变更仍需按更新器既有流程审核；本次没有绕过该保护。
